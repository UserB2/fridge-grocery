로그인 후 돌아올 기본 주소와 허용 주소에는 공개 사이트만 등록되어 있다. 독립된 저장 공간에서 검증하기 위해 잠시 허용한 `http://127.0.0.1:8767/`는 검증 후 제거했다.

공개용 프로젝트 연결 키는 코드에 반영했다. 비밀번호나 관리자 키는 포함하지 않았다. 무료 조직·무료 프로젝트를 사용하며 결제 정보나 유료 부가 서비스를 등록하지 않았다.

## 실제 확인 결과

1. 소유자가 Google 앱 정책 동의, 웹 OAuth 클라이언트 발급, Supabase Client ID/Secret 입력을 완료했다. 저장된 연결을 활성화했고 공개 인증 설정에서 Google 로그인 활성 상태를 확인했다.
2. 개인 Google 계정으로 미리보기와 공개 사이트에 각각 로그인했다. 두 주소는 브라우저 저장 공간과 로그인 세션이 서로 독립적이다.
3. 미리보기에서 ‘동기화 확인용 항목’을 저장하고 새로고침 후 서버에서 복원되는지 확인했다.
4. 공개 사이트에서 같은 기록을 불러와 이름을 수정했다. 미리보기 화면에 새로고침 없이 자동 반영됐다.
5. 미리보기에서 확인용 항목을 소진 처리했고 공개 사이트에서도 제거가 반영됐다. 확인용 항목은 남기지 않았다.
6. 미리보기에서 로그아웃했을 때 계정 기록을 숨기고 로컬 모드로 돌아왔고, 공개 사이트의 독립 로그인은 유지됐다.
7. 로그인하지 않은 공개 API 요청의 계정 기록 읽기는 HTTP 401로 거부됐다. 실제 PostgreSQL의 두 계정 역할 격리와 충돌 처리 등은 자동 테스트에서도 확인했다.
8. 자동 테스트 49개가 통과했고 공개 사이트 브라우저 오류·경고 로그는 비어 있었다. 서로 다른 실제 물리 기기를 조작한 검증은 아니며, 독립된 두 사이트 저장 공간을 사용했다.

## 이제 사용하는 방법

휴대폰과 컴퓨터에서 공개 사이트를 열고 프로필 메뉴 → Google로 로그인 → 같은 Google 계정을 선택한다.

이전에 쓰던 브라우저 기록은 로그인 후 프로필 메뉴의 ‘이 기기의 기존 기록 가져오기’에서 직접 선택한다. 다른 기기에 내보낸 JSON 파일이 있다면 ‘내보낸 목록 파일 가져오기’를 사용한다. 기존 로컬 기록은 자동 업로드하거나 삭제하지 않는다.

무료 요금제만 사용한다. 무료 한도 초과나 Supabase 비활성 휴면으로 동기화가 제한될 수 있으나 이 작업에서 유료 구독·결제 수단·도메인 구매는 추가하지 않았다.
